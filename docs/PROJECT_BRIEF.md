# 项目设计文档

## 项目名称

EnvForge

## 一句话定位

一个轻量、跨平台、带可视化界面的开发环境自动化部署工具，用一份清单完成工具安装、版本锁定、环境变量配置、验证和回滚。

## 背景问题

开发团队常见痛点包括：

- 新成员配置环境耗时，且依赖口口相传。
- 不同操作系统上的安装路径、包管理器和 shell profile 差异较大。
- 环境变量和 PATH 修改不可追踪，出错后难以恢复。
- 纯命令行工具对非资深用户不够友好，风险确认和问题定位成本高。
- Docker 能解决运行时一致性，但无法覆盖本机 IDE、SDK、CLI、证书、代理、密钥引用等本地开发细节。

## 目标用户

- 需要维护多项目开发环境的个人开发者。
- 需要统一 onboarding 流程的工程团队。
- 不熟悉命令行但需要配置开发环境的新人。
- 需要跨 Windows、macOS、Linux 协作的全栈、后端、AI、移动端团队。
- 希望把“环境配置”纳入代码审查的技术负责人。

## 产品入口

### 可视化桌面应用

桌面应用是默认推荐入口，负责降低理解成本：

- 自动扫描当前系统和已安装工具。
- 用清晰列表展示缺失、过期、冲突和可选组件。
- 提供可勾选的环境目录，用户可按语言、框架、AI/ML、数据库、DevOps、移动端等分类选择。
- 在执行前展示安装计划和环境变量变更。
- 以步骤进度、实时日志和错误建议展示执行过程。
- 提供一键验证和回滚。

### 命令行工具

CLI 面向自动化和高级用户：

- 可用于 CI、脚本和远程环境。
- 与 GUI 共用同一套核心引擎。
- 输出可机读 JSON，便于接入团队流程。

## 核心能力

1. 读取声明式环境清单。
2. 探测当前系统、架构、shell、包管理器和已安装工具。
3. 生成执行计划，展示将安装、修改、跳过和验证的内容。
4. 调用平台适配器安装工具和 SDK。
5. 安全写入用户级或项目级环境变量。
6. 记录变更快照，用于审计和回滚。
7. 执行版本、命令、端口、环境变量、文件存在性等验证。
8. 在 GUI 中呈现计划、风险、进度、日志和恢复操作。
9. 提供环境目录和模板，让用户勾选 C/C++、Java、Rust、AI 开发框架等环境后一键完成安装配置测试。

## 非目标

- 不做云端设备管理平台。
- 不替代 Docker、Nix、Ansible、MDM 或 CI/CD 系统。
- 不做复杂 IDE，不承载代码编辑能力。
- 不常驻后台，不默认启动 daemon。
- 不把所有软件规则硬编码进核心，而是通过 catalog、stack template 和 recipe 扩展。

## 轻量化原则

- 核心引擎和 CLI 使用单二进制交付。
- GUI 使用轻量原生外壳，不捆绑大型浏览器运行时。
- 默认不依赖数据库；本地状态使用 JSON 文件。
- recipe 是普通 YAML 文件，可放在项目仓库中。
- 不常驻后台；只在用户打开应用或执行命令时运行。
- 网络访问只在安装、更新 recipe 索引或下载依赖时发生。

## 成功标准

- 在一台新机器上，用户能通过 GUI 勾选并部署常见 Web、后端、C/C++、Java、Rust、AI/ML 等开发环境。
- GUI 首屏能清楚告诉用户当前环境状态、下一步动作和潜在风险。
- 用户勾选环境栈后，可以一键完成安装、环境变量配置、版本验证和示例测试。
- dry-run 能清晰展示风险变更，包括 PATH 和环境变量修改。
- 回滚能撤销 EnvForge 自己写入的环境变量和 profile 片段。
- 新增一个工具 recipe 不需要改核心代码。
- Windows、macOS、Linux 至少各支持一种主流安装路径。
